This document has been replaced

The original technical specification described the tool as it was first built: a browser-only application with no server and no database. That is no longer how it works, and it has been replaced rather than patched.

Why it was removed rather than corrected Its opening claim was “there is no server, no installation and no database”, and it described passwords being hashed in the browser. All application data now lives in a hosted PostgreSQL database, sign-in is handled by Supabase Auth with mandatory multi-factor authentication, and access is enforced by row-level security on every request. This file is publicly readable, so anyone reading the old text would have drawn precisely the wrong conclusions about the security model.

It has been split in two, because the two audiences need different things:

User and Administrator Specification

Every page, every record and field, every workflow, all nine access roles and the full permission matrix. Account management, onboarding, troubleshooting.

Open

Developer Specification

Architecture, the write seams, data model, security model, triggers, transactional workflows, and how to change, extend, maintain and debug it all.

Open

Both documents are generated by BUILD-SPEC-USER.mjs and BUILD-SPEC-DEVELOPER.mjs, which read the permission model and collection registry out of the source at build time — so the tables in them cannot drift from what the software actually does.
